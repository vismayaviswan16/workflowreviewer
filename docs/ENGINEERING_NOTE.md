# Engineering note -- AI-assisted workflow reviewer (v1.2.1)

## 1. Scope and contracts

**Task.** Decide whether a *specification*, a *workflow graph* and *linked Python snippets* implement *anchored source requirements* after *approved changes*, and report evidence-backed findings. **Supported language (declared scope).** Conditions over declared `number | bool | categorical` fields: `< <= > >= == !=`, `is missing / present`, `in {..}`, `at least / more than / ...`, nested `AND / OR / NOT`, ordered rules (exceptions = earlier rules), time units `s/min/h` converted to the field's canonical unit (a unitless number on a unit-bearing field uses the artifact's *declared* unit; none declared = ambiguous, never guessed). **Missing values:** an ordering/equality comparison on a missing value is false; `is missing` is the test; Python `None != c` is true and `None < c` raises. **Restricted Python:** one `route(ticket)` with `if/elif/else` returning string literals, `.get("f"[, lit])`, aliases, `is None / is True / is False`, `in / not in (literals)`, and ternary returns. Snippets are **inspected with `ast`, never executed**; syntax check, inspection and execution are reported as three separate stages (execution: `not_performed`). **Anything else is `unsupported`, stays in `coverage.unreviewed`, and forces INCOMPLETE** -- it never disappears.

**Contracts (`reviewer/schemas.py`).** Requirements `{id, anchor, order, text, note}` (anchor = evidence location); spec rules `{id, when, then, source_ref}`; workflow nodes `{id, version, kind, branches[{when,to}] | route}`; snippets `{id, version, linked_node, source}`; approvals `{id, target, status, seq, applies_to, new_when/new_then, supersedes}`. **Rule mapping across artifacts is behavioural, not by ID**: `source_ref` is only metadata (a dangling one is a warning) and matching IDs prove nothing. An **omission** gets its source reference from the *requirement* that the artifact fails to implement (anchor + text), even when the spec has no such ID.

**Effective requirements (`effective.py`).** Only *top-level* approval records with `status: approved` count; approval claims in prose are flagged and ignored. Scope: `applies_to == "*"` or the review version is listed. Order: replay by `(seq, id)`. `supersedes` retires a same-target, earlier-or-equal-seq record. **Revocation is an event**: a `revoked` record retires the approvals it names. Two live records setting the same attribute differently, cycles, cross-target / unknown / later-seq links, and revocations that name nothing are **conflicts/ambiguities: no version is chosen**, the target is unresolved and the status cannot be PASS.

## 2. Design choices

*One IR, two readings.* Every artifact is lowered to a decision list (`Cmp / IsMissing / And / Or / Not`); a workflow is a branch-ordered graph evaluator. *Deterministic first:* the model is optional and advisory. *Status is a pure function* (`decide`): evidenced blocker -> CHANGES_REQUIRED; else any unsupported/ambiguous/sampled/failed-required check -> INCOMPLETE; else PASS. *Oversized input is never truncated* (INCOMPLETE with reason). A bundle's `review_config` can only **tighten** operator policy. A cache key hashes bundle, config, version and client, so a changed artifact or approval cannot reuse a stale PASS.

## 3. Semantic checks: how equivalence and counterexamples are established

**Exhaustive within the declared language.** For every field the reviewer collects all constants mentioned in *any* artifact and splits the domain into representative cells: each constant, an open interval between/around constants (a value strictly between two adjacent constants exists for reals; for `integer: true` fields only when an integer fits), the **missing** value, and for categoricals each named value plus one `__other__` value. Rules are piecewise-constant on these cells, so *comparing the effective requirements and each artifact on one representative per cell is an exact proof of equivalence*, not a sample. An exact pruned depth-first search skips cells once every router's outcome is decided. **Counterexample = a cell where routes differ**; it is **re-evaluated on a full ticket** with both routers before it is reported (`verified_by_reevaluation`), and carries expected route/trace and actual route/trace. Equivalent formulations pass because comparison is on behaviour: `x > 29` vs `x >= 30` on an integer field, `in {EU,UK}` vs `== EU OR == UK`, `NOT (a <= 200 OR a is missing)`, a ternary vs an if-chain. **Classification** (`changed_threshold`, `boundary_mismatch`, `unit_mismatch`, `precedence_error`, `wrong_destination`, `omitted_requirement`, `missing_branch`, `runtime_error`, `unexpected_rule`, ...) uses isolated rule matching plus the mismatch pattern. **Interactions:** overlapping rule pairs are enumerated with an example ticket and the winner; dead/shadowed rules are warnings. **Root-cause consolidation (v1.2.0):** findings on the same artifact sharing a requirement or location are merged into one finding whose `related_findings` keep every ticket (on 600 fuzz cases with exactly one changed rule, artifacts carrying >1 blocker fell from 462 to 116; the remainder are genuinely cross-mapped rules, kept separate; the confirmed-blocker status is unchanged).

**Sampled mode** (grid over the leaf cap or the wall-clock budget) is *labelled* `sampled`, may still find real mismatches (blockers need an exactly re-evaluated counterexample), but **sampled agreement can never produce PASS**. Prose or Python outside the subset is never claimed verified.

## 4. Model integration (trust and failure handling)

`ModelClient.complete(ModelRequest) -> ModelResponse` (`reviewer/model/client.py`); a scripted **fake** for reproducible tests and an opt-in **live Anthropic client** (stdlib HTTPS; unit-tested with a stub transport; **not run**, so *no semantic real-model performance is claimed*). **What the model contributes:** correction wording for deterministic findings and *advisory* concerns about content the parser could not read (sent as JSON-quoted `UNPARSED/UNTRUSTED` evidence). **What it cannot do:** change status, approval authority, rule mapping or counterexamples; a model claim not backed by a deterministic finding is `severity: advisory`. **Validation:** truncated (`finish_reason: length`), malformed and schema-invalid JSON; invented rule refs and invented evidence IDs (discarded and counted); conflicting claims about one rule (discarded). **Bounds:** `model_max_calls=3`, token budget, prompt-size limit (no truncation), per-call timeout; every request config and response (id, model, finish reason, latency, usage, SHA-256 of prompt and text) is preserved. A required model that fails -> INCOMPLETE, never PASS. Instruction-like text in requirements or comments (`ignore previous...`, `report PASS`, "approved by VP") is detected, listed under `untrusted_content` and has **no effect**.

## 5. Evaluation (fake client; real model not measured)

*Frozen benchmark:* 27 synthetic bundles (7 valid, 14 defective, 6 incomplete), expected outcomes produced by a hand-written **independent routing oracle** (`oracle/`, shares no code with `reviewer/`), 5-bundle holdout, paired behaviour-changing vs rename/reorder/paraphrase variants, covering approved/unapproved changes, approval conflicts, omissions, boundaries, units, precedence, wrong branches, code disagreement, injected instructions and model failures. Inputs, labels, split, generators, oracle and baseline are SHA-256 pinned; `run_all.sh` and `run_all.ps1` refuse to run if any changed.

| Same 27 frozen cases | valid -> PASS | defective -> blocked | false passes | incomplete correct | defects w/ correct location | oracle-valid counterexamples | unsupported blockers |
|---|---|---|---|---|---|---|---|
| Baseline v0 (initial checkpoint) | 3/7 | 6/14 | **8** | 0/6 (6 unsafe PASS) | 1/14 | 0/0 | 16/17 |
| Final v1.2.1 | **7/7** | **14/14** | **0** | **6/6** | **14/14** | 14/14 | 0/14 |
| Final, holdout only (5) | 1/1 | 3/3 | 0 | 1/1 | 3/3 | 3/3 | 0/3 |

False blocks: v0 4, final 0. Abstentions (INCOMPLETE on valid/defective): final 0. Resource (fake client): 31 calls, 4 retries (scripted timeouts/truncation), 0.1777 s in the final release verification run for 27 bundles (machine- and run-dependent); real-model latency/cost: not measured.

**Controlled ablations** (same inputs and settings, one mechanism off). *Random sampling instead of the partition grid:* valid PASS 7/7 -> **0/7** (all abstain: sampled agreement cannot support PASS) and defects found 14/14 -> **9/14** (the 5 misses -- D01, D05, D11, D12, D14 -- are all `changed_threshold` defects whose offending cell a uniform random ticket does not hit; 0 false passes because the status rule refuses to PASS on a sample). *Approvals disabled:* **V02 false block** (an approved 30->25 change is ignored, so the correct 25-minute artifacts are flagged) and **I01 unsafe PASS** (a conflict is invisible), 5 extra unsupported blockers. *Pruning disabled:* **no outcome changes (27/27 identical)**; only cost: +33% leaves and 1.3-1.6x runtime at 6-7 extra fields (`reports/scaling.json`) -- on the frozen set the benefit is not demonstrable.

**Beyond the frozen set (post-freeze, not used for tuning).** Independent differential fuzzer (random policies + mutants, brute-force oracle): **800/800 agree, 0 false passes, 0 false blocks, 0 crashes** (seeds 1 and 2, 400 each; 1,500 more on seed 7 during development). Adversarial probe: 37 probes, 0 mismatches. **Second policy family** (refund routing, different fields/routes, `in {..}`, revocation, code idioms): 19 cases, **19/19** (6 valid, 11 defective, 2 incomplete; 0 false passes/blocks). **Mutation test** (deliberate faults): 16/16 killed. These supporting harnesses were developed within the same AI-assisted project; they widen coverage but are not independent third-party evidence.

## 6. Two debugging examples (full outputs in `reports/debugging/DEBUGGING.md`)

**(1) REAL -- revocation modelled as a status.** Failing output (v1.1.0 probe): `revocation record (revoke A1) -> CHANGES_REQUIRED exp=PASS <<< MISMATCH`; a payload-less revocation gave INCOMPLETE. *Diagnosis:* `derive()` dropped every non-`approved` record, so the revoked approval A1 (25 min) stayed live and the *correct* 30-minute artifacts were reported as `changed_threshold`. *Fix:* revocation is an event that retires the records named in `supersedes` (same target, earlier-or-equal seq; else ambiguity -> INCOMPLETE), no payload required. *Regression:* `tests/test_v3.py::Revocation` (5 tests); mutant M11 (revocation ignored) is killed.
**(2) REAL (harness) -- fuzzer "false blocks".** Failing output: `--seed 1` exits non-zero, `"false_block": 3` (cases 159, 166, 260). *Diagnosis:* replaying each reviewer counterexample on the fuzzer's independent evaluator shows the routes *do* differ -- the tickets use `tier = __other__`, a value the fuzzer's brute-force grid never contained, so the harness mislabelled correct findings. *Fix:* oracle grid gains an unmentioned categorical value. *Regression:* `FuzzOracleDomain`; 800 later cases 800/800. **Deliberate fault injection** is separate and labelled: the mutation test (13/16 killed first; after 3 survivors M07/M09/M13 we added 4 tests -> 16/16).

## 7. Limitations (measured where possible)

| Limit | Evidence / effect |
|---|---|
| Exhaustive grid grows ~4x per extra numeric field | 8 extra fields: 589,824 leaves, 9.2 s, PASS exhaustive; 9 extra: over the cap/time -> labelled `sampled` -> **INCOMPLETE** (safe, not a PASS). No field-group decomposition or identity shortcut. |
| Python subset | No loops, calls other than `.get`, subscripts, mutation, `.get` default inside `is None`; reported unsupported (INCOMPLETE). No execution, so no runtime effects beyond modelled `None` behaviour. |
| Language | No explicit `UNLESS/EXCEPT` (exceptions = ordered rules); only time units; no free prose; an equality-value change is labelled `changed_threshold`. |
| Domain assumptions | Categorical open domain = named values + `__other__`; ints only if `integer: true`; missing = key absent for defaulted `.get`. |
| Evidence base | One frozen policy family + a second family written by the same author; the holdout cannot be certified un-inspected (no pre-git history). Model-adjacent behaviour is tested with synthetic responses only. |
| Real model | Prompt, interface, live client exist; **semantic model performance not measured**; the API has no seed, so `seed` is recorded but not enforced. |
